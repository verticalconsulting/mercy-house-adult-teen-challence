# Support Escalation

Use this skill when a user issue needs to be handed off to a human support team.

## Escalate when

- the user reports a bug, outage, payment issue, or account/security issue
- the user is frustrated and asks for a human
- the request requires policy exceptions or manual investigation
- you do not have enough information to safely answer

## Before escalating

- collect the key facts:
  - user name or account email
  - order / invoice / case reference if relevant
  - what happened
  - what the user expected
  - urgency / deadline if mentioned

## Handoff summary format

Always produce a short summary in this format:

- Issue: [one sentence]
- User impact: [what is blocked or affected]
- Relevant details: [IDs, dates, plan, device, screenshots, etc.]
- Requested outcome: [refund, fix, clarification, callback, etc.]

## What to tell the user

- confirm that the issue is being escalated
- explain the expected response time: [Insert SLA or support expectation]
- tell them where the follow-up will happen: [Insert channel: email, ticket, phone, etc.]

## Never do

- do not invent internal actions that have not happened
- do not promise a resolution time unless it is part of the official support process
